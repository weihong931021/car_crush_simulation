# 發現：haware 定位器的座標系手性 bug（heading 系統性錯誤）

日期：2026-07-27（2026-07-28 更新：**已套用**）　範圍：`trafficlab-project/trafficlab/motion/haware_localization.py`

> **一句話**：`localize()` 的 Procrustes 排除了反射，但模板座標系映到衛星像素系
> **本來就需要反射**。後果是 heading 系統性錯誤（橫向主導的點集恰好錯 180°），修法是
> 一行。修之前的所有 heading 數字都不能當準確度用。

## 一、bug 是什麼

模板的座標約定（`build_car_template()` docstring）：

```
x: 橫向 — 正 = 車輛左側
y: 高度 — 0 = 地面
z: 縱向 — 負 = 車頭，正 = 車尾
```

衛星圖是**影像像素座標**（x 向右、**y 向下**）。車頭朝北（−y）時，車輛左側指向 −x、
車尾指向 +y，所以 body(x,z) → sat(x,y) 的映射是 `[[-1,0],[0,1]]`，**行列式 = −1**。
車輛旋轉只是左乘旋轉矩陣，det 恆為 −1：

```
M = [ℓ_left, r_rear] = [[f_y, -f_x], [-f_x, -f_y]],   det M = -(f_x² + f_y²) = -1
```

但 `localize()` 第 301–302 行強制 det = +1：

```python
det_sign = float(np.sign(np.linalg.det(Vt.T @ U.T)))
R = Vt.T @ np.diag([1.0, det_sign]) @ U.T  # 2×2 rotation (no reflection)
```

**強制 det=+1 就是排除唯一正確的解。**

### 誤差的確切形式

不是「隨機出錯」，而是**解析可預測**的：強制 det=+1 傳回的是
「正解 ∘ 繞該次點集主軸的反射」，因此

```
heading 誤差 = 2 × angle(點集主軸, 車體 z 軸)
```

實測驗證：|實際 − 預測| 中位數 0.00e+00、最大 1.14e−13 度（taipei-cm n=820、kee-cc n=892）。
**這是精確關係，不是近似。**

推論出的規律：

| 點集主軸方向 | heading | 位置 |
|---|---|---|
| 縱向主導（全 24 點、車頂群、四輪） | **正確** | 對稱點集可保持正確 |
| 橫向主導（擋風玻璃對、前燈對、同軸輪對） | **恰好錯 180°** | 錯 1.5–2.1 m |
| 同側輪對（共線） | **正確** | **恰好錯一個軌距 1.53 m** |

⚠️ 兩個容易誤導的直覺，實測都不成立：
- 「殘差為零 ⇒ 姿態正確」——**錯**。rank-1 的成對點集殘差恆為 0，卻可能 heading 錯 180°。
- 「殘差不為零 ⇒ 中心與 heading 都錯」——**也錯**。對稱點集的殘差不為 0，但中心與 heading 可以都正確。

### 影響範圍

| 站點 | status=ok | rank-2（非共線）子集 | 佔比 |
|---|---:|---:|---:|
| taipei-cm | 820 | 677 | 82.6% |
| kee-cc | 892 | 725 | 81.3% |

`det_sign = −1`（bug 實際開火）的比例：taipei-cm **36.2%**、kee-cc **91.6%**。

實際受損程度：

| 指標 | taipei-cm | kee-cc |
|---|---|---|
| heading 變動（修前 vs 修後）中位數 | **67.03°** | 26.76° |
| 其中 >90° 的比例 | **39.0%** | 16.0% |
| 位置變動中位數 | **1.520 m** | 1.382 m |
| 位置變動 >1 m 的比例 | 87.0% | 99.9% |

heading 的尾端最致命——180° 翻轉會讓正面對撞被重建成追撞。

## 二、修法（已用獨立 ground truth 判定）

```python
# haware_localization.py，localize() 內，第 294 行之後
Q = self.template[idx][:, [0, 2]] * s
Q[:, 0] = -Q[:, 0]        # ← 手性修正：body(x=左,z=後) → sat(x右,y下) 需要反射
# 第 301-302 行的 R 維持原樣，heading 公式 atan2(-R[1,1], -R[0,1]) 也維持原樣
```

### 為什麼是這個修法，不是其他兩個

| 候選 | 判定 | 理由 |
|---|---|---|
| **模板 x 取負** | ✅ **採用** | ground truth 驗證正確；forward 仍是 (0,−1)，heading 公式不用改 |
| 模板 z 取負 | ❌ | 數學上也能讓 det=+1，但 forward 變成 (0,+1)，沿用原 heading 公式**恰好錯 180°**（實測翻轉率 94–100%） |
| `R = Vt.T @ U.T`（允許反射） | ❌ | 代數上等價，但**只有 2 個關鍵點時 Hc 是 rank-1**，第二奇異向量任意 → det 由數值噪音決定。n=2 佔 taipei-cm 11.5%、kee-cc 18.7% |

**建議在 `localize()` 內局部翻轉 `Q`，不要改 `build_car_template()`**：模板的 x 欄還被
`localize_reprojection()`（第 472、489、500 行）讀，改模板會連帶擾動另一條路徑，
也會讓模板不再符合自己 docstring 的「x 正 = 車左」語意。

### Ground truth 證據

用兩個與手性無關的獨立參考：**行進方向**（由 keypoint 位移求得，完全不碰 R）與
**同側輪軸**（h=0，前/後標籤與左右手性正交）。兩參考互相驗證：輪軸 vs 行進方向
中位誤差 taipei-cm 1.25°、kee-cc 4.60°，翻轉率皆 0%。

taipei-cm track 53（文件裡唯一被判定「可用」的 track），對行進方向：

| | 現行 | **x 取負** | z 取負 |
|---|---:|---:|---:|
| 中位絕對誤差 | 92.11° | **2.28°** | 177.72° |
| 180° 翻轉率 | 54.2% | **0.0%** | 100.0% |

（Codex 用不同的 course proxy 獨立得到 93.27° → 6.50° → 173.50°，結論相同。）

無標籤佐證（Procrustes 殘差 RMS，與 heading 定義無關）：kee-cc 1.585 → **1.094 m**
（改善 31.0%，79.7% 的 detection 變好）。taipei-cm 幾無變化，因為它的殘差被 homography
外推誤差主導（見第四節）。

## 三、必須連帶修正的既有結論

### `openpifpaf-apollo24.md` §5 的「track 53 可用、heading 抖動 5.0°」要重寫

那個 5.0° 量的是**抖動（精密度）不是準確度**。實測：現行程式下 track 53 的逐幀
heading 抖動確實只有 4.95°，但對獨立行進方向的**系統性偏差是 93°**。

原因：同一條 track 的 keypoint 組成穩定 → 反射軸穩定 → 偏差近似常數 → 看起來又穩又乾淨。
而且位置誤差是近似常數的車體座標平移，所以**軌跡形狀與速度剖面幾乎不變**
（逐幀步長中位數修前修後都是 0.373 m），只是整條平移約 1.5 m。

「沿道路的乾淨軌跡」與「heading 錯 93°」可以同時成立。

track 53 也**不是**以輪子為主：376 個關鍵點裡輪子只佔 17.0%、車頂 25.8%、其他 57.2%。

### 所有既有的 heading／中心數字都要重跑

修正後 taipei-cm 中心移動中位數 1.520 m、kee-cc 1.382 m。任何比較估計器優劣的結論
都必須在修正後重新計算。

## 四、順帶查出的其他問題

### 1. taipei-cm 不適合當驗收場地

它有**獨立於本 bug 的 homography 度量缺陷**：用 h=0（免疫視差假設）的輪對量觀測軸距，
模板值是 2.546 m，但實測中位數 **5.92 m**，落在合理區間 2.0–3.2 m 的只有 **12.5%**；
kee-cc 同一檢定通過率 **53.2%**（中位數 3.18 m）。

加上它的 z_cam = 3.596 m 是 repo 內 8 個地點最低（1/k 幾何懲罰 1.85× vs kee-cc 1.29×，
衛星平面各向異性中位數 15.7× vs 7.7×），**建議改用 kee-cc / taoyuan-tc 驗收**。

### 2. z_cam 被系統性高估 15–22%

以 h=0 輪群為錨反推 η = h/z_cam，兩個站點方向一致：
taipei-cm 車頂與車燈兩族群獨立都指向 z_cam ≈ 2.8 m（設定 3.596）、
kee-cc 指向 5.7–6.5 m（設定 7.419）。輪子自洽檢定隱含 h = −0.00 m（IQR [−0.05, 0.06]，
n=522），確認輪子確實在地面。

### 3. `localize_reprojection()` 有同型問題（程式碼推論，未實測）

`_rotation_from_vectors()` 的 docstring 明寫 "Proper 2D rotation"，同樣排除反射。
它又是**逐對**算 heading，所以不同關鍵點對會給出互相矛盾的角度——method 2 用
`_LR_PAIRS`（純橫向 body 向量）應同樣吃到 180° 誤差；method 1 用前→後輪向量則免疫。
程式裡的「heading 一致性投票」很可能就是在替這個問題打補丁。

### 4. PifPaf 的 `front_up_right`（索引 0）在 kee-cc 有語意錯位

以 h-免疫的右側輪組當車體軸參考：

| 關鍵點 | 修正後模板 (x,z) | 觀測中位數 (x,z) | 縱向落差 |
|---|---|---|---|
| 0 front_up_right | (+0.63, −1.04) | (+0.11, **+0.81**) | **+1.86 m**（robSD 0.08） |
| 1 front_up_left | (−0.63, −1.04) | (−0.62, −0.78) | +0.27 m（robSD 0.14） |

觀測到的 0→1 線段：橫向 0.746 m、**縱向 1.538 m**，比值 2.02——**這根本不是一條
擋風玻璃寬度的線段**。索引 0 穩定地落在側車頂區域而非擋風玻璃角，影像疊圖也吻合。

這解釋了先前觀察到的「擋風玻璃對有 +64° 系統性偏移」：**不是物理現象、不是視角相依**，
是單一關鍵點的語意錯位。因此任何基於「視角相依偏移」的線上校準設計都不成立。

**建議的閘門**（有輪子時）：拒絕畸形的左右線索

```
|(P₁ − P₀) · f| / |(P₁ − P₀) · ℓ| < 0.25        # f=車頭方向, ℓ=車輛左方向
```

實測接受 taipei-cm 71/71、拒絕 kee-cc 159/159。0.25 這個門檻在跨視角資料驗證前算暫定值。

## 五、關於「擋風玻璃當主力」的結論

原始問題是：擋風玻璃的關鍵點跨多支影片看起來最穩定最準，能不能拿它當軌跡主力？

**結論：目前資料無法支持，但前提沒有被推翻。**

- 「擋風玻璃對散度最小（robSD 1.56°/2.0°）」這個數字可以重現，但那組樣本在**兩個站點
  各自只來自一台靜止車、單一視角**（100% 落在同一個 45° 區間，熵 0.00 bits）。
  這不是「精密」，是「在單一靜止條件下穩定」。
- 同車同幀的配對比較：kee-cc 的擋風玻璃**輸給**前燈對（1.56° vs 1.01°）。
- 在唯一能量準度的移動車上：輪軸對行進方向中位誤差 **1.61°/0.99°**，擋風玻璃 **91.79°**。

**但幾何上有個更根本的理由，與偵測品質無關**：

> 2 像素的雜訊 → 擋風玻璃對 heading 散度 **16.4°**，同側輪對只有 **2.1°**（8 倍差距）。

因為擋風玻璃基線只有 1.26 m 且是**橫向**的，輪距是 2.55 m **縱向**。所以
**擋風玻璃的點可以是全場偵測最準的，而擋風玻璃「對」仍然是最差的 heading 估計器**——
兩件事不矛盾。

### 那擋風玻璃該怎麼用

它的**射線方位角**（從相機天底點看出去的角度）極準（0.01–0.018°/px，與輪胎同級），
而且**對高度先驗完全免疫**（視差校正是繞天底點的均勻縮放，所以射線方向與 h 無關）。

→ **朝向交給輪軸，擋風玻璃貢獻位置/方位。** 這是互補而非取代。

另外已證明的架構約束：**heading 擬合絕不可跨高度族群**。單一高度族群的 heading 對
高度先驗誤差**嚴格免疫**（擾動 ±0.15/±0.30 m，heading 變化 0.0000°，n=612）；
但把輪子併進車頂群一起擬合，同樣擾動會造成 **15.16°** 變化——比現行全點混合（5.33°）更糟。

## 七、可信度邊界

**可外推**：手性 bug 與其修法（純程式約定，與地點無關，兩站點同時證實）、
誤差 = 2×主軸夾角的解析關係、單一高度族群 heading 對 η 免疫、跨族群混合會摧毀免疫性、
高點的幾何懲罰 = 1/k = 1/(1−h/z_cam)、短基線放大雜訊的量級關係。

**不可外推**：所有絕對誤差數字（67°、1.52 m、16.24° 等）、η 與 z_cam 的站點校準值、
關鍵點可見度統計（是視角性質）、索引 0 的語意錯位（目前只在 kee-cc 觀察到）。

**已知的證據弱點**：taipei-cm 只有 4 台獨立車輛（13 條 track 中僅 4 條 >100 幀）；
kee-cc 那份輸出**完全沒有 tracking**（tracked_id 全同），per-vehicle 統計只能用
最近鄰偽軌跡；「擋風玻璃」相關的所有結論都建立在各站一台靜止車上。
